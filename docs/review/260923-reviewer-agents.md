## [P1] SQL 수집을 위한 테스트 실행이 읽기 전용 DB 경계를 위반한다

- 위치: `.claude/agents/query-plan-reviewer.md:65` (권한 경계: 83행).
- 발생 조건: 리뷰어가 생성 SQL을 얻으려고 기존 리포지토리 테스트를 실행하고, 테스트 환경이 데이터가 있는 로컬 MySQL을 가리킨다.
- 근거: `src/test/resources/application.yml`은 기본 `localhost:3306/fmarket`과 `spring.sql.init.mode=always`를 사용한다. `src/main/resources/schema.sql:1`부터 테이블 DROP/CREATE를 수행한다. `OrderRepositoryTest`는 실제 DB 대체를 금지하며 테스트 데이터 INSERT도 한다. 따라서 이 절차는 SELECT/EXPLAIN/SHOW만 실행한다는 자체 규칙과 양립하지 않고 기존 데이터를 초기화할 수 있다. 테스트 메서드의 롤백을 초기화 방지 수단으로 볼 수 없다.
- 수정 방향: 기존 DB에서의 SQL 수집용 테스트 실행을 금지한다. 테스트는 폐기 가능한 별도 DB임을 확인한 경우로 제한하고, 격리 환경이 없다면 기존 SQL 로그·정적 분석을 사용해 생성 SQL과 실행 계획을 미검증으로 보고한다. 테스트 허용 예외와 DB 권한 경계도 함께 정리한다.
- 검증 방법: 기존 DB만 제공된 상황에서 테스트를 실행하지 않는지, 별도 테스트 DB를 제공했을 때만 SQL 수집을 수행하는지 리뷰어 호출로 확인한다.
- 조치: 수정함. query-plan-reviewer 는 호출자가 폐기 가능한 DB 라고 명시한 경우에만 리포지토리 테스트를 실행하고, 아니면 코드에서 재구성한 "추정 SQL" 로 보고한다. 같은 위험이 있는 test-quality·consistency·security 리뷰어의 테스트 실행 규칙에도 같은 제한을 넣었다.

## [P2] 이전 계약을 main으로 고정하면 요청한 변경 범위를 놓친다

- 위치: `.claude/agents/api-contract-reviewer.md:18`, 같은 지침 반복: 83행.
- 발생 조건: 미커밋 변경 리뷰 또는 main 이외 브랜치를 대상으로 하는 PR 리뷰.
- 근거: `git diff main...HEAD`는 인덱스와 작업 트리 변경을 포함하지 않는다. 현재 실행 결과도 이번 신규 리뷰어 파일 대신 기존 커밋의 스킬 분리 변경을 보여 준다. 또한 merge-base 기준 diff와 `git show main:<경로>`의 main 최신 파일은 main이 분기 후 진전했을 때 서로 다른 기준이다. 이 조합으로는 계약 변경을 누락하거나 무관한 변경을 회귀로 판단할 수 있다.
- 수정 방향: 호출자가 지정한 대상에 따라 기준을 정한다. 미커밋 리뷰는 HEAD 대비 작업 트리·인덱스와 신규 파일을 확인하고, PR 리뷰는 대상 브랜치와 merge-base를 사용한다. 이전 파일도 선택한 동일 기준 커밋에서 읽는다.
- 검증 방법: 미커밋 DTO 필드 변경, main 이외 대상 브랜치, main이 분기 후 진전한 경우를 각각 입력으로 주어 비교 대상이 일치하는지 확인한다.
- 조치: 수정함. 미커밋은 HEAD, 브랜치는 merge-base, PR 은 base 커밋을 기준으로 정하고 `git show <기준>:<경로>` 로 같은 기준에서 이전 파일을 읽게 했다. 5절의 반복 지시도 같은 기준을 참조하도록 고쳤다.

## [P2] RequireLogin 부재만으로 인증이 없다고 판단한다

- 위치: `.claude/agents/security-reviewer.md:23`.
- 발생 조건: `@RequireLogin`은 없지만 `@LoginUserId` 인자를 갖는 엔드포인트를 검토한다.
- 근거: `LoginUserIdResolver.resolveArgument`는 세션 사용자 ID가 없으면 `BusinessException(LOGIN_REQUIRED)`를 던진다. 이 리졸버는 `WebConfig`에 등록돼 있으며 `docs/API_RESPONSE.md`도 두 애너테이션 모두의 401 경로를 명시한다. 따라서 "붙이지 않으면 인증 없이 열린다"는 단정은 실제 인증된 경로를 인증 누락으로 오탐하게 한다.
- 수정 방향: AOP와 인자 리졸버의 두 인증 경로를 함께 설명하고, 어느 경로에서도 세션이 검사되지 않는 경우에만 인증 누락으로 판단한다. 소유권 검사는 별도로 유지한다.
- 검증 방법: `@LoginUserId`만 갖는 컨트롤러 경로에 대한 기존 계약 테스트와 리졸버 코드를 근거로, 인증 누락으로 보고하지 않는지 확인한다.
- 조치: 수정함. 인증 구조 절에 AOP 와 리졸버 두 경로를 적고, 둘 다 없을 때만 인증 누락으로 판단하게 했다. `DELETE /cart/{id}` 는 둘 다 없어 기존 BACKLOG 항목은 유효하다.

## 검증 및 제한

- 신규 파일 전체와 추적 파일 diff를 읽고 관련 스킬, API·테스트 문서, 인증 리졸버·등록 설정, 주문·장바구니 컨트롤러와 서비스, DB 테스트 설정·스키마를 대조했다.
- `git diff --check` 통과. 이 명령은 미추적 파일을 검사하지 않는다.
- BACKLOG의 기존 주문 소유권 검사 누락과 장바구니 삭제 인증·소유권 누락은 현재 코드에서 확인했다. 이번 변경이 만든 결함과 구분했다.
- Gradle 테스트·DB 접속·EXPLAIN·실제 리뷰어 호출은 실행하지 않았다. 문서 변경 리뷰이며, DB 테스트 초기화 위험은 설정과 스크립트로 확인했다.
