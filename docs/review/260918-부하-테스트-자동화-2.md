## 발견 사항

### P2 — user-flow 의 로그인 실패가 실행 실패로 이어지지 않는다

대상: `performance/k6/user-flow.js:54-57`, `performance/k6/lib/auth.js`

일부 VU 만 로그인에 실패하면 `throw` 는 그 iteration 만 끝내고 k6 실행은 실패하지 않는다. 로그인 요청은 `phase:login` 태그라 `checks{phase:main}` 밖이고, `login()` 은 check 도 카운터도 남기지 않아 나머지 VU 가 threshold 와 DB 불변식을 전부 통과하면 동시성이 줄어든 채로 "성공" 이 된다.

검증: 코드 대조로 사실 확인. `login()` 에 check 가 없고 `baseThresholds` 에 로그인 관련 항목이 없었다.

조치: **수정함.**
- `lib/auth.js`: `login()` 이 `login 200 OK`·`login sets session cookie` check(phase 태그)를 남기고, 실패 시 `login_failures` 카운터를 올린다.
- `lib/thresholds.js`: `login_failures: count==0` 을 공통 threshold 에 추가. setup 에서 로그인하는 경합 시나리오까지 같이 보호된다.
- `user-flow.js`: 로그인 실패 시 `exec.test.abort()` 로 실행을 중단한다 (측정 조건 자체가 깨진 상태라 계속 돌 이유가 없다).
- 재실행(20 VU × 20s): `login_failures: count==0` PASS, 나머지 threshold·DB 검증 통과.

### P2 — 워크플로의 잔여 정리 단계가 실제로는 동작하지 않는다

대상: `.github/workflows/load-test.yml:79-80`

`docker compose ls --format` 은 `table`/`json` 만 받으므로 `'{{.Name}}'` 은 파싱 오류가 나고 루프에 아무것도 들어오지 않는다. 열거를 고쳐도 `down` 이 Compose 파일을 다시 해석하면서 앞 단계에서만 export 된 `RUN_ID`·`LOADTEST_RESULTS_DIR` 등을 요구해 실패한다.

검증: 로컬 재현.
- `docker compose ls -a --format '{{.Name}}'` → `format value "{{.Name}}" could not be parsed`
- 환경변수 없이 `docker compose -p x -f performance/docker-compose.loadtest.yml down -v` → `required variable MYSQL_REPLICATION_PASSWORD is missing a value`

조치: **수정함.** Compose 를 거치지 않고 `com.docker.compose.project` 라벨로 컨테이너(`rm -f -v`, 익명 볼륨 포함)·볼륨·네트워크·이미지를 직접 지운다. `--keep` 으로 남긴 실행(컨테이너 3, 네트워크 1, 이미지 1)에 같은 스니펫을 돌려 전부 제거되고 개발용 Compose 자원은 남는 것을 확인했다.
