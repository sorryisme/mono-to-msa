# 리뷰 전용 서브에이전트 5종 추가

- 일자: 2026-09-23
- 요청: 기존 `java-spring-reviewer` 외에 동시성·정합성, 테스트 품질, 보안, SQL 쿼리 검증 리뷰어 추가

## 배경

리뷰어는 구현과 리뷰를 겸하는 `java-spring-reviewer` 하나뿐이었다. 금지 패턴·의존 방향 같은 기계적 검사는 훅과 CI 가 담당하므로, 새 리뷰어는 판단이 필요한 영역에만 둔다.

## 추가한 파일

| 파일 | 담당 영역 |
|---|---|
| `.claude/agents/consistency-reviewer.md` | 재고·주문 상태 전이·멱등성 불변식, 트랜잭션 경계, readOnly 라우팅, 벌크 UPDATE 와 영속성 컨텍스트, 경합 인터리빙 |
| `.claude/agents/test-quality-reviewer.md` | 테스트 누락, 단언의 힘, 검증 약화, mock 테스트의 증명 범위 과장, docs/TESTING.md 관례 |
| `.claude/agents/security-reviewer.md` | `@RequireLogin` 누락, 리소스 소유권(IDOR), 역할 권한, 대량 할당, 세션·비밀번호 처리, 로그·응답 민감 정보, 설정·CI 비밀 |
| `.claude/agents/query-plan-reviewer.md` | 복잡한 SELECT 의 인덱스 사용·filesort·풀 스캔·N+1, 읽기 전용 EXPLAIN. 단순 단건 조회와 쓰기 쿼리 제외 |

`CLAUDE.md` 문서 구성 목록에 네 에이전트를 추가했다.

후속 요청으로 security-reviewer 에 기본 웹 취약점 점검 항목을 추가했다. SQL·JPQL 인젝션(문자열 연결, 정렬 속성, `JpaSort.unsafe`, LIKE 와일드카드), 로그 인젝션, CSRF, 저장형 XSS, 세션 쿠키 속성, 명령·경로 인젝션, SSRF·오픈 리다이렉트, 역직렬화, 자원 고갈, 무차별 대입을 다룬다. 보고서에는 항목별 결과(결함·안전·해당 경로 없음)를 담은 점검표를 추가했다.

## 공통 설계

- 도구는 Read·Grep·Glob·Bash·Skill 만 준다. Edit·Write 가 없어 리뷰 중 파일을 고칠 수 없다.
- 심각도 P0~P3 와 발견 사항 서식은 `java-spring` 스킬의 "리뷰 모드의 판단과 출력" 절을 참조해 결과를 한 리뷰 문서로 합칠 수 있게 했다.
- 영역 경계를 본문에 명시했다. 락·트랜잭션의 동시성 의미는 consistency, SELECT 의 실행 계획·인덱스는 query-plan, 범용 보안 점검은 내장 `/security-review` 가 맡는다.
- 각 리뷰어는 발견 사항에 재현 근거를 요구한다. 동시성은 요청 인터리빙, 테스트는 통과해 버리는 결함의 예, 보안은 공격 요청, 쿼리 성능은 생성 SQL 과 EXPLAIN 결과다.
- query-plan-reviewer 는 DB 에 SELECT·EXPLAIN·SHOW 만 허용한다.

## 작업 중 발견 (BACKLOG 로 보류)

- 주문 취소·확정·상세 조회가 소유권을 검사하지 않는다.
- 장바구니 상세 삭제에 인증과 소유권 검사가 없다.
- `docs/ARCHITECTURE.md` 가 제거된 비관적 락 메서드를 설명한다. 코드는 조건부 UPDATE 를 쓴다.

## 검증

- 소스 코드 변경은 없다. 에이전트 파일의 프런트매터 형식을 기존 `java-spring-reviewer.md` 와 대조했다.
- 본문에 적은 설정 사실(`ANSI_QUOTES`, `lower_case_table_names=1`, `PageableSupport` 동작, 인증 구조)을 코드·설정 파일에서 확인했다.
- 실제 호출 테스트(각 에이전트로 리뷰 실행)는 하지 않았다. 새 에이전트는 세션을 다시 시작해야 목록에 나타날 수 있다.

## 후속 변경: SQL 리뷰어를 실행 계획 전용으로 축소

- 요청: SQL 리뷰어는 SELECT 성능만 보고, 단순 단일 쿼리는 무시하며, 복잡한 쿼리가 인덱스를 통해 조회되는지를 검토하도록 변경.
- 이름을 `sql-query-reviewer` 에서 `query-plan-reviewer` 로 바꿨다. 결과 정확성·쓰기·스키마 검토가 빠지고 실행 계획과 인덱스 사용만 남아, 이름이 범위를 드러내도록 했다.
- 대상 선별 기준을 명시했다. 조인·동적 조건·범위+등호 혼합·정렬+페이징·count·LIKE/IN/OR·집계·증가하는 테이블의 다건 조회는 검토하고, PK·유니크 단건 조회, 인덱스 컬럼 하나의 등호 조회, 고정 소규모 기준 데이터, 쓰기 쿼리, performance/sql 은 제외한다.
- `data.sql` 시드가 소량이라 EXPLAIN 결과를 "인덱스 후보 확인"까지만 근거로 쓰고, 대량 데이터 판단은 구조적 근거로 분리하도록 했다.

## 후속 변경: API 계약 리뷰어 추가

- 요청: API 계약 확인 리뷰어 추가.
- `.claude/agents/api-contract-reviewer.md` 를 추가하고 `CLAUDE.md` 목록에 등록했다.
- 계약의 단일 출처를 `docs/API_RESPONSE.md` 와 `ErrorCode` 로 두고, 봉투 형식, 상태·코드 매핑, 예외 핸들러 경로, 성공 상태(200·201), 요청·응답 DTO 의 하위 호환성, `@Valid` 누락, `Page` 직렬화, `Idempotency-Key` 헤더 계약, 문서·계약 테스트 동기화를 본다. 인증·소유권은 security-reviewer 영역으로 남겼다.

## 후속 변경: 외부 리뷰 지적 반영

- 요청: `docs/review/260923-reviewer-agents.md` 의 지적 3건(P1 1, P2 2)에 대한 수정 검토.
- 세 건 모두 코드로 사실을 확인했다. 테스트 설정의 `spring.sql.init.mode=always` 와 `schema.sql` 의 `DROP TABLE`, `git diff main...HEAD` 의 미커밋 변경 제외, `LoginUserIdResolver` 의 `LOGIN_REQUIRED` 처리다.
- [P1] DB 초기화 위험: 리포지토리 테스트는 호출자가 대상 DB 를 폐기 가능하다고 명시한 경우에만 실행한다. query-plan-reviewer 는 실행하지 못하면 코드에서 재구성한 SQL 을 "추정 SQL" 로 표시한다. 지적은 query-plan-reviewer 에 한정됐지만 test-quality·consistency·security 리뷰어도 DB 테스트를 실행할 수 있어 같은 제한을 넣었다.
- [P2] 비교 기준: api-contract-reviewer 가 미커밋·브랜치·PR 대상별로 기준 커밋(HEAD·merge-base·PR base)을 고르고, 이전 파일도 같은 기준에서 읽는다. 새 파일(`??`)은 diff 에 나오지 않으므로 직접 읽게 했다.
- [P2] 인증 판단: security-reviewer 가 `@RequireLogin`(AOP)과 `@LoginUserId`(리졸버) 두 경로를 모두 인증으로 인정하고, 둘 다 없을 때만 인증 누락으로 본다. 이 기준으로도 `DELETE /cart/{id}` 는 둘 다 없어 기존 BACKLOG 항목은 유지한다.
- 리뷰 문서의 조치 결과와 BACKLOG 세 항목을 완료로 갱신했다.
