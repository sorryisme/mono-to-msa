# CI 정합성 수정 — 줄바꿈·액션 런타임·sql_mode

- 작업일: 2026-09-11
- 결과: verify 워크플로 그린 (전 스텝 success, Node.js 20 deprecation 경고 0건)
- PR: #2

## 1. Java 소스 줄바꿈 LF 통일

Java 파일이 저장소(오브젝트 DB)에 CRLF 로 저장돼 있었다. Spotless 는 Git 속성을 따라
줄바꿈을 결정하므로, 속성이 없으면 Windows 로컬과 Linux CI 의 포맷 결과가 갈릴 수 있다.

- `.gitattributes` 에 `*.java text eol=lf` 추가
- 기존 Java 파일 71개를 LF 로 재정규화 — 내용 변경 없이 줄바꿈만 바뀌었고,
  `git diff --stat` 의 순증감 +3 줄은 전부 `.gitattributes` / `docs/CODE_STYLE.md` 몫이다
- `.gitattributes` 자체가 CRLF/LF 혼재였어서 LF 로 정리
- `docs/CODE_STYLE.md` 의 Spotless 대상 표기를 실제 `build.gradle` 설정(`src/**/*.java`)에 맞추고
  줄바꿈 정책 문단 추가

## 2. upload-artifact 액션 상향 (v5 → v7)

러너가 다음 경고를 냈다.

```
Node.js 20 is deprecated. The following actions target Node.js 20 but are being
forced to run on Node.js 24: actions/upload-artifact@v5
```

`v5` 는 `runs.using` 이 여전히 `node20` 이라 러너가 강제로 node24 로 올려 실행한다.
`v6` 부터 `node24` 가 기본이 되었고(최소 러너 2.327.1 요구), 현재 최신은 `v7` 이다.
사용 중인 입력(`name` / `path` / `if-no-files-found`)은 v7 에서도 그대로 지원되어 v7 로 올렸다.

`actions/checkout@v5`, `actions/setup-java@v5` 는 action.yml 확인 결과 이미 `node24` 라 두었다.

## 3. CI MySQL 에 ANSI_QUOTES 적용 (선행 이슈)

이 브랜치 이전(`49e5c04`)부터 CI 는 이미 레드였다. 매퍼 테스트 28건이
`BadSqlGrammarException` 으로 실패했고, 실제 메시지는 다음과 같았다.

```
You have an error in your SQL syntax; ... near '"USER"(login_id, password, ...)'
```

매퍼 SQL 은 `"USER"` 처럼 식별자를 쌍따옴표로 인용하는데, MySQL 기본 sql_mode 는
쌍따옴표를 문자열 리터럴로 해석한다. `docker-compose.yml` 은 이 이유로 이미
`ANSI_QUOTES` 를 지정하고 있었지만, CI 워크플로는 옵션 없이 `mysql:8.4` 를 기동하고 있었다.

- CI 의 `docker run` 에 `--sql-mode=...,ANSI_QUOTES` 와 `--lower-case-table-names=1` 추가
- 로컬 테스트가 통과했던 이유: 로컬 DB 가 이미 해당 sql_mode 로 떠 있어서
  CI 환경과의 차이가 드러나지 않았다

## 남는 것

- 로컬 MySQL 의 sql_mode 에 의존해 통과/실패가 갈리는 구조 자체는 그대로다.
  매퍼 SQL 의 식별자 인용을 백틱으로 바꾸거나 Testcontainers 로 DB 기동 조건을
  코드에 고정하면 이 부류의 환경 의존을 없앨 수 있다.
